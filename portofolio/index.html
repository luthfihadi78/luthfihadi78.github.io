01 · the system

One pipeline, from a websocket tick to a number I have to defend

Qkuk is not a screener with a Telegram bot attached. It is a loop: ingest market data, detect a setup, publish a signal whose entry, stop and target are frozen at publication, resolve it against the price that actually printed, then feed the result back into the statistics that decide whether the engine keeps running.

  1. 01

    Ingest

    Binance USD-M futures for ≈470 pairs, plus spot, funding, open interest, long/short ratio and CoinGecko market caps. Requests are throttled across processes and cached.

    REST · klines · ticker/24h
  2. 02

    Detect

    Four engines read different timeframes with different concepts — sweep-and-reclaim, premium order blocks, BTC-relative gates. Each returns a setup, or nothing.

    Python · pandas · NumPy
  3. 03

    Gate

    Before a strategy is allowed to trade, it has to survive deflated Sharpe, probability of backtest overfitting and combinatorial purged cross-validation on 700+ days.

    SciPy · walk-forward OOS
  4. 04

    Publish

    Signal text to the group, state to data.json, digest at 18:00 WIB. The web layer only ever reads that file — no credentials in the browser.

    Node · JSON · GitHub Pages
  5. 05

    Resolve

    Every signal is scored when it hits TP or SL. Live win rate comes from resolved picks only, never from the backtest, and the history page is generated from that record.

    CSV → JSON → HTML
  6. 06

    Supervise

    A supervisor daemon restarts anything that dies, and a DoH fallback keeps the exchange reachable when the local resolver stops answering.

    respawn · throttle · DoH

02 · engines

Four engines that are allowed to disagree

Each engine is a separate hypothesis about where liquidity sits. They run on different timeframes, publish into separate channels, and are scored separately — so a bad month in one cannot hide inside the average of four.

BRICK1h → 30m

Order block, taken only in the direction of the trend

A premium order block is only a signal if price touches it while EMA200 agrees. The 1h block defines the zone; the 30m structure decides whether the touch is worth taking.

  • Concept: premium OB + EMA200 filter
  • Gate: none beyond structure — the honest one
  • Output: entry, stop, 2R target, tier
HARVEST2h

Liquidity sweep, reclaim, then short

Short-only by construction. Price sweeps a swing high, fails to hold it, and closes back inside the range — the engine sells the failed auction, not the breakout.

  • Concept: sweep + reclaim + imbalance
  • Bias: short only
  • Why short-only: the mirror long variant did not survive the gate
SCALP 2H2hpromoted

The engine that replaced SWING 4H

Premium order blocks on the 2h, confirmed by structure rather than by a moving average. It took over when SWING 4H's out-of-sample expectancy decayed below the cost of trading it.

  • OOS expectancy: +0.197R
  • Sample: 3,637 trades over 12 months
  • Positive months: 10 of 13
  • Deterministic: same input, same signal
BASTION4h

Order block with a market-wide permission slip

The 4h block is the zone, but the trade only exists when BTC has moved more than 1% in the last 24 hours. Without that, the block is a drawing.

  • Concept: premium OB + BTC 24h gate > 1%
  • Bias: follows BTC direction
  • Purpose: fewer, larger, market-aligned trades

Two engines are switched off on purpose. SWING 4H was retired when its out-of-sample expectancy fell to +0.044R — still positive, but no longer worth the risk it consumes. Wyckoff was retired after failing the gate. Both are still visible in the archive so the record cannot be rewritten, but neither produces signals any more. A system that never kills an engine is not being measured; it is being defended.

03 · the terminal

Every screen answers one question, and none of them hide the answer

The terminal is plain HTML, CSS and JavaScript — no framework, no chart library, no build step. It polls one JSON file, draws its own canvas and SVG, and is designed to stay readable on a phone in a café. Below is what each part actually does.

3.1 · bubbles

A market map that only shows the coins the engines care about

What it is. A physics canvas of floating bubbles. Each bubble is one coin that appears in the engines' record — not the whole market. The number inside is the live 24-hour change pulled from Binance, not an R multiple.

What it is for. A table tells you what happened. Bubbles tell you where the attention is: a screen of green means the whole book is running; one red giant on an otherwise green field is a single coin being dumped while everything else is fine. That distinction changes whether a setup is a market call or an idiosyncratic one.

  • Size is the absolute 24h move — a −30% coin is as big as a +30% coin, so panic and euphoria are equally visible.
  • Colour is direction: green up, red down, sand when Binance has no 24h data. The fallback chain is futures → spot → CoinGecko → CoinPaprika, and the source is labelled on screen.
  • Fire aura marks a coin the engine has on record today, so a big mover that no engine flagged is visibly different from one that was already in the book.
  • Gold ring and ★ mark a coin an admin actually picked, with the chosen side and status (waiting / in position / took profit) written inside the bubble. When two admins pick the same coin with opposite sides, the bubble shows both with a ⚔ badge instead of silently overwriting one.
  • Drag and collide: press and hold to move a bubble, release and it floats again. Bubbles collide elastically, so clusters are stable enough to read.
  • Search highlights a symbol with a pulsing ring; tap opens its TradingView chart.

3.2 · composite gauge

One needle, three inputs, and an honest way to say "I don't know"

What it is. A direction gauge for altcoins built from three factors: BTC's own direction, the breadth of the reclaim group (how many pairs are actually being reclaimed, not just how loud the movers are), and stablecoin-dominance behaviour.

What it is for. Engines fire per pair; a trader still has to decide whether to be aggressive. The gauge is that decision compressed into six states — long, strong long (altseason), neutral, short, strong short (crash) and a degraded state.

  • When a factor is missing, the gauge says degraded and explains which input is gone. It never fills the gap with a guess.
  • Values are deliberately damped: it was rebuilt after the first version was too twitchy to be useful, and the damping rule lives in one place shared with the Python side.
  • Old signals stop counting after a fixed window, so yesterday's winner cannot hold the needle forever.
  • The page background follows the gauge state — calm, altseason, or crash — because the first thing you look at should be the regime.

3.3 · signals & watchlist

The whole lifecycle of a trade, in one table

What it is. A live feed of every signal from every engine, plus the watchlist — setups that were detected but have not triggered an entry yet.

What it is for. A signal is a claim about the next few hours; the table is where the claim is either confirmed or quietly falsified. Entry, stop and 2R target are set at publication and never re-drawn afterwards, so a signal cannot be "fixed" after the fact.

  • Sort by newest, picked first, best or worst R, or pair name. Filter by long or short. Search by symbol.
  • 🔥N marks a pair that several engines flagged independently — consensus is measured, not assumed.
  • Each row carries engine tag, timeframe, entry, stop, target, live R, and the admin's decision where one was made.
  • Watchlist sits in the same feed rather than a separate page: a setup that is being watched is part of the record too.

3.4 · live statistics

Win rate measured from resolved picks, not from the backtest

What it is. Four views of the same record: cumulative equity per channel, win rate by hour of the day (WIB), a head-to-head leaderboard between the two people who pick from the feed, and a what-if equity curve that asks "if every engine signal had been taken with fixed risk, where would the account be?"

What it is for. Backtests flatter you; resolutions do not. The hour-of-day chart exists because the same engine is not equally good at 03:00 and 20:00, and the leaderboard exists because two humans picking from the same feed is a natural experiment about discretion.

  • Only resolved picks count. Open positions are carried as open, never scored as wins.
  • The what-if curve is labelled as a simulation over the last ≈100 signals per channel — it is not presented as a track record.
  • A statistics reset date is applied deliberately, and the archive keeps the older data, so "starting fresh" cannot erase history.

3.5 · riwayat & archive

History that is pre-rendered, so it cannot quietly change

What it is. A monthly net-percentage bar chart and a table of every resolved pick, generated from a daily snapshot of the picks database. Next to it, a raw daily archive.

What it is for. The live page is optimistic by nature — it shows what is open. The history page shows what closed, which is the number that decides whether the system is worth running.

  • Pages are rebuilt from a snapshot rather than queried live: zero APIs, zero credentials, and a page that still loads when the exchange is down.
  • When an engine is retired, its picks are filtered out of the view and the monthly curve is recalculated from the remaining rows — so the chart never mixes a dead engine's results into a live one's.
  • Each row is one decision: timestamp, engine, symbol, side (including admin corrections), result, and who picked it.

3.6 · market context

Big caps top 50 and the derivatives backdrop

What it is. A table of the 50 largest crypto assets — stablecoins and wrapped tokens removed, because they do not move and would distort every average — plus a strip of funding rate, open interest, long/short ratio and fear & greed.

What it is for. An alt signal is a relative call. If the top 50 are all down 4% and an engine flags a long, that is a different trade from the same signal on a green day. The sorts — including worst 1h / 24h / 7d, not just best — make rotation visible in both directions.

  • Sorts: market cap, best and worst 1h/24h/7d, position in the 24h range, BTC correlation, volume, open interest, distance from all-time high.
  • A yellow dot marks a coin the engines flagged today, so market context and signal list line up by symbol.
  • An alert fires when at least 16 coins move 1% or more within an hour — breadth, not a single headline.

3.7 · daily digest & delivery

One message at 18:00 that a human can act on

What it is. A daily digest assembled from the same state the terminal reads: every live channel with its signals, a dedicated block per high-conviction engine, and a short summary of what resolved.

What it is for. Not everyone keeps a browser tab open. The digest is the product for people who want one readable message a day instead of a stream of alerts.

  • When an engine is retired it disappears from the digest and from the state file, so an old channel cannot keep posting because a cached file still remembers it.
  • A separate news engine watches for market-moving headlines and an economic calendar warns before scheduled volatility; both are opt-in context, never entry signals.

04 · the indicator

My own ICT indicator, because the engine should be checkable by eye

Qkuk ICT Concepts is a Pine Script v6 indicator I wrote for TradingView. It is not a signal generator — it is the chart version of the same vocabulary the engines speak: market structure, order blocks, imbalances, liquidity and inducement. If the bot says "sweep and reclaim" and the chart does not show a sweep, one of the two is wrong, and that disagreement has caught real bugs.

Market structure

MSS and BOS with configurable pivot length; MSS is a shift, BOS is continuation. Drawn as lines with labels, not arrows stacked on every candle.

Displacement

Body-dominant candles measured against the mean body, with an optional marker. Displacement is what makes an imbalance worth respecting.

Volume imbalance

Bodies that do not overlap while wicks do — the quiet gap that price tends to revisit. Capped to the last N so the chart stays readable.

FVG & BPR

Fair value gaps with break styling, plus balance price range (the overlap of the newest bullish and bearish gap) and implied FVG afterward.

Order blocks

ATR-impulse engine: impulsive candle ≥ 1.5× ATR, small base, close through the base. Zones are mitigated when price closes through them, and kept grey instead of deleted if you want the history.

Buyside / sellside liquidity

Clustered swing levels with breach zones — the levels where stops sit, and what happens after they are taken.

Liquidity sweep

Wick through the last swing by a configurable ATR buffer, with an optional reclaim requirement. This is the same trigger the HARVEST engine uses.

CISD

Change in state of delivery: the open of the first candle in the current delivery run, and the close that breaks it. One line at a time, because that is all it is.

Inducement (IDM)

A small state machine: lead leg → MSS with a penetration floor in ATR → the minor opposing swing after the MSS → the touch that completes the setup. The research engine's sequence, made visible.

EMA, VWAP, volume profile

Three configurable EMAs; session VWAP with ±1σ and ±2σ bands; POC and 70% value area over the last N bars. Context, not entries.

MACD, Fibonacci, killzones

MACD in its own lower panel (not overlaid on price), Fibonacci between the last two structures of your choice, and New York / London / Asian session shading.

IFVG sniper

Inverted fair value gaps with a quality filter (gap size in ATR, body ratio, range), theme packages, and invalidation — kept separate from the structural modules rather than welded into them.

Why an indicator at all? Because a black box you cannot look at is a black box you cannot debug. Building the same concepts twice — once in Python for the engine, once in Pine for the chart — forces every definition to be explicit: what counts as a sweep, how far a close must penetrate to be an MSS, which swing is "the last one". Half the engine fixes in this project started as a disagreement between the two implementations.

05 · operations

The unglamorous half: keeping it alive, and keeping it honest

A trading system that only works on the machine where it was written is a demo. Most of the work in Qkuk is not the strategy — it is the supervision, the failure handling, and the rule that the published number is the one that actually happened.

Supervisor, not hope

Every long-running process is registered with a supervisor daemon that restarts it on exit and logs the restart. Data publishers, pick backups and the watcher all come back on their own.

Throttle across processes

Engines, watchers and the dashboard all hit the same exchange. A shared token-bucket state file means parallel processes cannot collectively exceed the rate limit.

Fallback when DNS lies

When the local resolver stopped answering for the exchange host, a DNS-over-HTTPS path with a cached answer kept the engines running instead of failing every request.

Publishing that cannot clobber

The publish job fetches and resets before writing, stages only the files it owns, and refuses to commit if anything else got staged. It has never deleted another person's work — after an earlier version did.

State that does not resurrect

Retiring an engine removes it from the state file and the digest, not just from the UI. A cached channel cannot keep posting after the code that produced it is gone.

Numbers with a date on them

Backtest figures, live figures and simulations are labelled separately, every time. When a backtest bug was found (the resolver scored a window before the signal existed), the results were re-run and the engine's status changed — not quietly re-tuned.

What this is for

I would rather show you the receipts than the résumé line

Qkuk Terminal is one person's answer to a simple question: if a system is going to tell people where to put money, what should it be willing to show them? My answer was everything — the frozen entry, the losing month, the engine that got switched off, and the code that had to be rewritten when it was wrong. That instinct is what I would bring to an exchange: money movement is a domain where the reconciliation either closes or it does not.
